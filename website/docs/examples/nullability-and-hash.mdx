---
title: Nullability and Hashing
---

`nullable_test.dart` and `hash_code_test.dart` demonstrate how Zorphy treats
nullable fields and large field counts.

## Nullable fields

```dart
@ZorphyEntity(principalKey: #id)
abstract class $ErrorLog {
  String? get id;
  String get message;
  String? get userId;
  Map<String, dynamic>? get deviceInfo;
  DateTime get timestamp;
}
```

Nullability is preserved in generated constructors, `copyWith`, and the wire
codecs. A deliberate `null` on a nullable field decodes as a clear value, never
as a failed read.

## Large hashCode

```dart
@ZorphyEntity(principalKey: #id)
abstract class $LargeClass {
  String get id;
  String get f1;
  String get f2;
  String get f3;
  String get f4;
  String get f5;
}
```

For large models, Zorphy splits hash calculations for stability and performance.
