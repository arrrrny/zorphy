---
title: Polymorphism
---

Zorphy supports closed unions and open hierarchies. In v3 polymorphism is
declarative: a closed set of sibling variants is a `@ZorphyUnion()`, and an open
hierarchy is a `@ZorphyState()` root whose subtypes the generator infers from the
same-library declarations (or that you list with `explicitSubTypes`). This page
combines `sealed_class_example.dart` and the domain entities like `$Attachment`
and `$ChatMessage`.

## Closed union

```dart
@ZorphyUnion()
abstract class $PaymentMethod {
  String get displayName;
}
```

Concrete variants implement the union root:

```dart
@ZorphyEntity()
abstract class $CreditCard implements $PaymentMethod {
  String get cardNumber;
}
```

## Open hierarchy with explicit subtypes

A `@ZorphyState()` root keeps the base open while still enabling polymorphic
wire dispatch. Subtypes in another library are listed with `explicitSubTypes`.

```dart
@ZorphyState(explicitSubTypes: [$FileAttachment, $LinkAttachment])
abstract class $Attachment {
  String get name;
  String get mimeType;
}
```

```dart
@ZorphyState(explicitSubTypes: [$UserMessage, $AssistantMessage])
abstract class $ChatMessage {
  String get text;
  ChatMessageRole get role;
}
```

## Why this matters

- Safe polymorphic wire dispatch keyed on the `kind` discriminator.
- Strong typing when switching on subtype.
- Clear separation between base contracts and concrete classes.
