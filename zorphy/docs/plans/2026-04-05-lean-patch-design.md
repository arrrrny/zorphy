# Lean Patch Generation Design

## Overview
Reduce the total lines of code generated by Zorphy for `Patch` classes. Currently, the generator duplicates massive amounts of boilerplate (mostly JSON serialization logic and `Map` management) into every single entity's patch class. The new design extracts this logic into a shared base class, preserving the fluent API while dramatically reducing code size.

## Architecture Changes

### 1. `zorphy_annotation` (Runtime)
We will introduce a new base class, `PatchBase<TEntity, TEnum extends Enum>`, which implements the existing `Patch<TEntity>`.
This class will absorb all shared boilerplate:
- The internal storage map: `final Map<TEnum, dynamic> patchMap = {};`
- `toJson()`: Loop that converts the enum keys to strings.
- `_convertToJson()`: The massive switch/type-check logic for dates, enums, lists, maps, and nested objects.

### 2. `zorphy` (Code Generator)
In `lib/src/helpers.dart`, we will refactor `getPatchClass` to:
- Make the generated `[Entity]Patch` extend `PatchBase<[Entity], [Entity]$>`.
- Remove the generation of `create()`, `fromPatch()`, `toPatch()`, `toJson()`, `fromJson()`, and `_convertToJson()`.
- Preserve the generation of fluent `withX(Type value)` and `withXPatch(Patch patch)` methods, simply having them write to `patchMap[Enum.field] = value`.

## Impact
- **Developer Experience:** 100% backward compatible. Users will still have the exact same fluent nested patching API.
- **Code Size:** Reduces generated code by ~50-80 lines per entity.
